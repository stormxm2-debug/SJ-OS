## 6단계 결과 (v1.0.60 구현 — 검토 대상)

청구 관리 = **조회된 진료마다 청구 여부를 직원이 직접 표시하고, 상태별로 모아 보고 출력하는 기능**. 실제 보험 접수·보험사 청구 이력 자동 조회가 아님(화면 첫 줄에 "조회된 진료마다 보험 청구 여부를 직접 표시합니다. (보험사 청구 내역 자동 조회 아님)").

- 상태 select → `전체 / 확인 필요 / 미청구 / 청구 완료` 건수 버튼(`aria-pressed`, 선택 버튼 남색). 건수는 현재 기간·검색·진료 유형을 적용하고 상태 필터만 뺀 같은 기반 목록에서 집계 → 세 상태 합 = 전체. 상태 미조회·조회 중·조회 실패이면 상태 건수 `-`, 버튼 비활성, 행은 `상태 미조회`. 저장된 states에 없는 키는 조회 성공(ready) 후에만 `확인 필요`.
- 내부 상태값(`unknown/unclaimed/claimed`)·기록 키·인쇄 상태 라벨(`CLAIM_LABELS`)은 그대로. 화면 표시만 `CLAIM_VIEW_LABELS`(unknown→`확인 필요`).
- 목록 기본 행: 선택·날짜·병원·병명(+원자료 좌우)·청구 상태·자세히 보기(PC 6열 헤더=행 grid 동일, 375px 카드). 날짜는 `validCareDate` 검증값만 `YYYY.MM.DD`. 질병코드·진료 구분·입원일수·수술 추정/독감약/본인부담 30만 원 이상 표시·처방약 전체(이름·성분·투약일수)·치료 내용·표시한 날은 자세히 보기로 이동(누락 없음). 약 이름은 기본 행에 표시하지 않음(검색은 기존처럼 약 이름 포함).
- 선택 시 `청구 완료로 표시`(큰 주요 버튼) + 접힌 `다른 상태로 표시`(미청구/확인 필요). 체크 = 대상 선택(저장 아님) 짧은 문구·체크박스 이름 `… 대상 선택`. 반복 설명은 접힌 `이용 안내`로.
- `되돌리기`: 마지막 성공 저장 1건. `미청구 N건 출력`: 기간·검색·유형 범위의 미청구만(상태 필터·체크 선택 무관), 준비 전/0건/저장 중 비활성. `현재 목록 N건 출력` 유지. 기존 `printCareRecords` 사용.
- 변경 없음: 서비스 API·DB·RLS·권한·실제 접수/자동 청구 이력·기관 인증·AI·원격 러너, 한눈에 요약(v1.0.59)·기간·KPI·가입 검토·고객 전환 가드. 탭은 계속 한 번 마운트+표시 전환.
- 남은 한계: 되돌리기 동시성(RELEASE v1.0.60 참고). 화면 `확인 필요` / 인쇄물 `미확인` 라벨이 다름(인쇄 서비스 미변경).

## 5단계 결과 (v1.0.58 구현·독립 QA 완료)

한눈에 요약을 **기간 선택 → 핵심 숫자 3개 → 최근 진료 → 자세히 보기** 순서로 정리.

- 기본 기간 **최근 3개월('3m')**. 3개월/1년/3년/5년/전체 단일 선택이 핵심 숫자·최근 진료·자세히 보기·청구·가입 검토·AI 입력에 함께 적용(기존 공통 기간). RecentCareTable의 고정 3개월 예외 제거. 기간 선택은 저장된 결과의 표시 필터이며 기관 조회·인증·AI 호출 없음.
- 핵심 숫자: `진료기록 N건`(기존 건수 의미, 방문 중복 제거 아님) / `입원일수 약 N일`(일수 미확인 입원은 `일수 미확인 N건`, 확인된 일수가 없으면 `확인 필요`) / `수술 추정 N회`. 기록 0건이면 입원·수술은 `-`(0으로 단정 안 함). 미청구 카드는 요약에서 제거(청구 관리 탭 유지).
- 최근 진료 목록: 날짜·병원·병명(+원자료의 왼쪽/오른쪽)·처방약 요약만. **v1.0.59 후속: 기본 행·PC 헤더에서 처방약 열 제거(4열: 날짜·병원·병명·자세히 보기), 처방약 이름·성분·투약일수는 행별 자세히 보기에서만 표시. 약만 있는 기록도 자세히 보기 버튼 유지.** 질병코드·진료 구분(입원 일수)·수술 추정·치료 내용·처방약 성분/투약일수는 행별 `자세히 보기`. 모바일 건별 카드, PC 정렬 목록, 기본 6건 + 전체 보기.
- 목록과 숫자는 같은 계산(`careListSummary` / `careKpis`, 둘 다 `buildCareRecords(filterCareResult(result, period))`).
- 빈 결과: "선택한 기간에 조회된 기록이 없습니다" + `전체 기록 보기`. 날짜 미확인 기록은 "날짜 미확인 N건은 전체 기록에서 볼 수 있습니다" 한 줄.
- 정리한 문구: 탭 아래 사용법(요약 탭), 기간 반복 안내, 요약의 확인 권장/고액 띠, 결과 제목의 원자료 행 수, `명칭 기반`·`진료일·기관 일치 기반`·`적용 기간 버튼과 무관`·`코드 미제공`·`연결된 약물 없음`. 처리 방식·자료 범위·기록 없음 ≠ 이상 없음 설명은 접힌 `자료 안내`로 모음. 원자료(JSON)는 `자세히 보기` 안에서만.
- 용어: 상병→병명(요약·자세히 보기 보기 방식), 약물→처방약, 세부 진료·약물 보기→자세히 보기, 기간 `조회 전체`→`전체`.
- 변경 없음: 청구 저장/필터/출력 로직, 가입 검토·AI, 원본 수집, 고객 전환 가드·목록 refresh, 인증/기관 API/DB/RLS.
- 남은 한계: 청구 관리 탭의 검색 안내·헤더는 기존 용어(상병·약물) 유지. 기본 기간이 3개월이므로 청구 관리 탭도 처음엔 최근 3개월만 보임(기간을 바꾸면 저장 상태를 다시 읽기만 하고 덮어쓰지 않음 — 기존 동작). 실제 Electron 앱·실고객 데이터로는 미검증(합성 데이터 브라우저 검증만).

  예외 `updatedAt`은 "자료 수정일"로 표기(공식 심사 기준일 아님). 반복 경고는 접힌 "자료 기준 안내"로 이동.
- **3. AI 참고 요약**: 한 줄 설명 + 큰 실행 버튼, 질문 입력은 접힌 "질문 추가(선택)"(기존 `aiQ` 유지).
  기준 상태 안내(기준 미확인·선택 0·미매칭·부분/전체 실패·연결 N건) — 기준 없어도 실행은 막지 않음, 기준 조회 중에만 대기.
  분석 중 / 실패 + 다시 시도 / 완료 상태 표시. 기간 내 기록 없으면 기존 실행 불가 안내.
- 보존: 버튼을 눌러야만 기준 조회·AI 호출, `runAi`/`aiGeneration`과 `[result, carePeriod, underwritingContext]` 변경 시 답변 초기화·지연 응답 무효화,
  Workspace 단일 인스턴스(청구 검색·필터·선택·펼침, 실손 입력). `listUnderwriting`/`listExceptions` 호출·매칭 규칙·서비스·AI 프롬프트 변경 없음.
- 리뷰 보완(검토 대기 유지): AI 안내 건수 = 실제 AI 전송분(검수된 기준만, 검수 전 제외 명시), 보험사 picker 실제 접힘(클래스 display 제어),
  세부 조건 펼침을 보험사명에 귀속, 선택된 확장 보험사 옵션 유지. 검증은 RELEASE 문서 '보완 검증' 참조(합성 하네스 17/17 보고, 최종 375px 화면은 캡처 문제로 미확인, 실제 앱·AI 미검증).
