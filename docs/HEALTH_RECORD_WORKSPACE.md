# 건강기록 업무 화면 개선 — 2026-11-05

## 적용 위치

SJ 앱의 기존 **고객 건강기록 조회 → 조회 결과**에 구현했습니다.
별도 Python 검토 앱을 앱 안에 넣지 않고 기존 React·CODEF·Supabase·AI 서비스와 연결했습니다.
현재 작업 브랜치: `feat/health-record-workspace`.

## 구현한 기능

- 고객 주민번호를 직원 기기에 입력하지 않도록 기존 **고객에게 링크** 방식을 기본 선택했습니다. 기존 링크 발급·문자·고객 페이지를 그대로 사용합니다.
- 3개월 / 1년 / 3년 / 5년 / 조회 전체 필터. 표·기존 묶음·상병 요약·AI 입력이 같은 기간을 사용합니다.
- 병원·상병·질병코드·약물 검색, 입원·통원·수술 추정·확인 필요 분류.
- 원자료의 좌우와 질병코드 표시. 정보가 없으면 미확인 처리합니다.
- 원자료 입원일수 요약 및 묶음 카드 일수. 같은 날짜·기관은 최대값을 한 번 합산하지만 연속 입원·다기관 중복은 추가 확인이 필요합니다.
- 독감 치료 성분·약물명을 담보 확인 대상으로 표시. 실제 약품 마스터나 지급 약관을 대신하지 않습니다.
- 미확인 / 미청구 / 청구 완료 수동 저장, 일괄 변경, 상태별 필터와 현재 목록 인쇄·PDF 저장.
- 청구 상태는 원본 요청의 새 `claim_states` 필드에 저장합니다. 원자료를 추가 복제하거나 브라우저 영구 저장소에 넣지 않습니다. 상태는 이 저장된 조회에만 적용되며 새 조회와 자동 대조하지 않습니다.
- 통합 인수 검토: 기존 인수 가이드·유병자 예외질환을 불러와 병명·별칭 정확 일치 기준과 보험사별 조건을 한 화면에서 확인합니다. 기존 독립 메뉴는 유지합니다.
- AI 요청에 선택 보험사와 검수된 매칭 기준을 함께 전달합니다. AI는 인수에 영향을 줄 사실·확인 사항 위주로 요약하고 상품명·가입 가능 여부를 지어내지 않도록 서버 지침을 추가했습니다.
- 대기 경과 시간, 오류별 다음 조치, fetching·consented 요청 폴링, 시간초과 후 최근 요청 확인 안내.
- 월말·윤년·현지 날짜 기준 계산 보정, 실제 달력 날짜 검증.
- 로그에서 외부 CODEF 응답 메시지를 제거했습니다. 개인 식별자를 포함할 수 있는 원문 응답을 진단 로그에 남기지 않습니다.

## 검증

- `npm run typecheck`: 통과
- `npm run build`: 통과 (Electron main/preload/renderer)
- `npm run build:web`: 통과. 기존 대형 번들 경고는 남아 있습니다.
- `SJ_HEALTH_SQL_QA_DIR=/tmp/sj-health-sql-qa npm test`: **179개 통과, 1개 생략** (총 180개). 기존 실제 Postgres 검사 1개는 initdb 미설치로 생략됐습니다. 신규 도메인·저장 어댑터·AI 컨텍스트·인쇄 테스트 16개와 격리 SQL 검사 1개가 포함됩니다. QA 엔진 미설치 환경에서는 선택 SQL 검사도 생략됩니다.
- 신규 SQL 검사는 별도로 **격리 PGlite PostgreSQL 엔진에서 통과**: 다른 직원 접근, 본인 저장·재조회, 관리자 접근, 만료·동의 철회, 익명 호출, 잘못된 상태·키·건수 및 일괄 변경 원자성을 검증했습니다.
- 실제 브라우저·휴대폰 렌더링 및 인쇄 페이지 나눔은 미검증입니다.
- 실제 CODEF 호출·고객 인증·보험사 기준 내용·모델 응답 정확도·운영 DB는 검증하지 않았습니다. 운영 고객 데이터를 조회하지 않았습니다.

선택 SQL 검사 실행(운영 DB를 사용하지 않음):

```bash
npm install --prefix /tmp/sj-health-sql-qa --no-audit --no-fund @electric-sql/pglite
SJ_HEALTH_SQL_QA_DIR=/tmp/sj-health-sql-qa node --test test/hrClaimStateRls.test.mjs
```

## 운영 적용 순서

운영에는 아직 적용하지 않았습니다. main 푸시는 기존 PWA 자동 배포를 트리거하므로 작업 브랜치로 전달합니다.

1. 기존 `health_record_requests` 스키마·RLS 및 30일 보관 정책을 확인합니다.
2. `supabase/migrations/20261105_health_record_claim_states.sql`을 적용합니다. additive 변경이며 기존 결과를 삭제·이동하지 않습니다.
3. `health-record-ai`를 새 `underwritingContext.ts`와 함께 배포합니다. `health-record-fetch`도 변경된 로그 동작을 반영하려면 배포합니다.
4. 스테이징에서 본인·다른 FC·관리자 계정으로 청구 상태 저장·재조회·철회·만료를 확인합니다.
5. UI를 검토한 뒤 PR을 main에 병합해 기존 PWA 배포 파이프라인을 사용합니다. 데스크톱 설치본은 별도 릴리스가 필요합니다.

DB 변경 미적용 시 저장은 실패 안내를 표시하고 성공으로 가장하지 않습니다.
AI 함수 미배포 시 기존 함수는 추가 컨텍스트를 사용하지 않으므로 새 요약 지침은 적용되지 않습니다.

## Claude Code 연결 상태

공식 CLI를 실행해 `claude auth status`를 확인했습니다: **loggedIn=false / authMethod=none**.
이 환경에서 Claude 모델 작업은 실행하지 않았습니다. 구현·검증은 Codex가 수행했습니다.
기존 앱의 Claude Auto Builder·Runner·IPC 구조는 수정하지 않았습니다.
로그인된 개발 PC에서 [검토 작업 지시문](CLAUDE_HEALTH_RECORD_REVIEW.md)을 Claude Code에 전달할 수 있습니다.
계정 비밀번호나 API 키를 코드·문서·대화에 붙여넣지 마세요.

## 남은 요구사항

- 심평원 오전 9시 이전 오류·내가먹는약 주민번호 오류·외국인 이름 오류의 실제 원인 확인. 공식 API 스펙·비식별 로그 없이 암호화나 이용 시간을 추정 변경하지 않았습니다.
- 한 개 링크에서 여러 기관을 연속 인증하고 전체 자료를 합치는 흐름. 현재 기존 상품별 링크를 유지합니다.
- 계약·급여/비급여·약관 버전·잔여 한도 기반 실손 세대별 실제 예상 지급액. 금액을 임의 계산하지 않습니다.
- 실제 보험사 청구 이력 자동 대조, 담보별 일부 청구·지급 완료 상태, 재조회 간 기록 연계.
- 공식 상품별·기준일별 인수 판정. 현 인수 가이드는 보험사×질환 수준이고 특정 상품·기준일이 없는 행이 있으므로 최종 가입 가능·불가로 표시하지 않습니다.
- 한장보험료 비교와 자동차보험 API 연결.

## 되돌리기

프런트엔드는 해당 변경 이전 버전으로 되돌릴 수 있습니다. 추가한 DB 필드·함수는 이전 프런트엔드에서 사용하지 않으므로 즉시 삭제할 필요가 없습니다.
고객 기록·수동 확인 이력을 삭제하는 DB 롤백은 이 문서에서 수행하지 않습니다.
