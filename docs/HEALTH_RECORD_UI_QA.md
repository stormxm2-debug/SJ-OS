# 건강기록 UI 독립 검증 — v1.0.58

검증일: 2026-11-08 (Asia/Seoul). 최종 앱 소스: `ea68e85814396961104ec96e8f2665a4f1e8a36d` (PR #99). 구현은 Claude Code, 계획·독립 검토·브라우저 QA는 Codex가 담당했습니다. 아래 문서 갱신은 앱·테스트 소스를 바꾸지 않습니다.

## 화면 검증

- 실제 `ResultReport`·`HealthRecordWorkspace`·`RecentCareTable`과 프로젝트 CSS를 Chromium/Playwright에 번들했습니다. 기관·고객·AI 등 서비스는 합성 mock이며 외부 접속을 차단했습니다.
- PR #98 `ca8bf9fa71a0c05d285927c6b857732628f0596c`: 핵심 브라우저 시나리오 **19/19 통과**. 기본 3개월, 핵심 카드 3개, 모든 기간의 기록 수·목록 일치, 날짜 미확인 기록의 전체 접근, 입원일수 미확인을 0일로 표시하지 않음, 빈 기간에서 전체 기록 복구를 확인했습니다.
- 질병코드·약 성분·투약일수·치료·입원·수술 상세 열림과 좌우 표시를 확인했습니다. 저장된 요청의 합성 청구 상태·검색·유형·선택·실손 입력·보험사 선택은 탭 전환에서 유지됐으며 기간 변경 후에도 기존 청구 상태를 보존했습니다.
- 위 동작에서 청구 저장·새 기관 조회·인증·AI 자동 호출은 없었습니다. 기존 청구 상태 읽기는 허용된 동작입니다.
- 최종 PR #99: `validCareDate`를 적용한 날짜 표시 보완과 최종 화면 **7/7 통과**. 존재하지 않는 날짜 `20260230`과 빈 날짜는 `날짜 미확인`, 유효 날짜는 정상 표시하며 미확인 날짜는 최근 기간에서 제외됩니다. 앱·테스트·패키지 blob 대조 결과 PR #98 대비 앱 변경은 이 표시 보완뿐입니다.
- 모바일 실제 viewport: innerWidth / clientWidth / visualViewport.width / scrollWidth = **375px**, scale 1. PC는 **1280px**. 최종 화면을 직접 확인했으며 가로 잘림·페이지 런타임 오류·외부 요청 시도는 없었습니다. 캡처는 로컬에만 보관했고 공개 저장소에 올리지 않았습니다.

# 건강기록 UI 독립 검증 — v1.0.57

검증일: 2026-11-08 (Asia/Seoul). 검증한 앱 소스: `bcad9f70714e9bf3209428b18fc65cc2295368a0` (PR #97).
앱 구현은 Claude Code가 담당했고, Codex의 독립 검토·브라우저 QA에서 아래 결과를 확인했습니다.
이 문서와 검증 기록 추가 후에도 앱·테스트 소스는 위 커밋과 동일합니다.

## 검증 환경과 범위

- 실제 `HealthRecordPage`·`ResultReport` 및 프로젝트 Tailwind 설정을 번들해 Chromium/Playwright에서 실행했습니다.
- 인증·목록·기준 조회·청구·AI 서비스만 합성 mock으로 교체하고 외부 네트워크를 차단했습니다.
- 실고객 자료·실제 인증·DB·AI 호출은 없었습니다. 미리보기의 이름·연락처·기록은 합성 자료입니다.
- 검증용 체크아웃은 원본 앱 소스를 수정하지 않았습니다.

## 실제 모바일 화면 확인

이전 v1.0.56 하네스의 'PC 화면을 375px 이미지에 축소'한 캡처는 검증 근거에서 제외했습니다.
이번에는 앱과 하네스에 정상 viewport meta를 사용하고 다음 값을 실제로 측정했습니다.

| 화면 | innerWidth | documentElement.clientWidth | visualViewport.width | scrollWidth | visualViewport.scale |
| --- | ---: | ---: | ---: | ---: | ---: |
| 진행·긴 오류, 모바일 | 375 | 375 | 375 | 375 | 1 |
| 가입 검토, 모바일 | 375 | 375 | 375 | 375 | 1 |

PC는 1280px viewport와 배율 1에서 확인했습니다. 화면에서 긴 오류와 가입 검토 내용의 줄바꿈·가로 잘림을 확인했습니다.
실제 휴대전화 하드웨어·스크린리더 검증을 대신하는 것은 아닙니다.

## 실제 브라우저 동작

최종 소스에서 실제 브라우저 20개 시나리오가 모두 통과했습니다. 주요 검증 범위:

- 시간초과·네트워크 오류의 주 행동은 목록만 1회 새로고침하며 인증을 추가 호출하지 않음.
- 목록 갱신 실패 시 이전 목록·이전 목록 안내를 유지함.
- 늦은 이전 검색 응답이 최신 검색 결과를 덮지 않음.
- 새 링크·고객·상품 변경 후 이전 성공과 결과를 제거함.
- 가입 검토 탭에 들어가는 것만으로 AI를 호출하지 않음.
- 진행 중인 A 고객의 start 완료·invite 링크, 이전 상품 완료가 바뀐 화면에 표시되지 않음.
- 이전 요청의 종료 처리가 B 고객의 새 요청 로딩을 풀지 않으며 B의 정상 응답은 적용됨.
- 저장 결과 열람·입력 방식 전환 후 늦은 confirm/invite 응답이 화면을 덮지 않음.
- 요청 변수는 진행 중 잠기지만 고객·상품 전환은 가능함.
- 11초 걸리는 동일 검색 응답이 10초 폴링에 폐기되지 않고 단일 조회로 완료됨.
- 유효하지 않은 보관 날짜의 결과 열람을 차단함.

페이지 런타임 오류와 외부 요청 시도는 관찰되지 않았습니다.

## 단위 검사와 코드 검토
